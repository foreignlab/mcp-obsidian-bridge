## Recent Changes の原因

`/Users/foreignlab/.local/share/mcp-obsidian-tls/src/mcp_obsidian/obsidian.py:345` の `get_recent_changes` は、次の DQL を `/search/` へ送信する。

```text
TABLE file.mtime
WHERE file.mtime >= date(today) - dur(90 days)
SORT file.mtime DESC
LIMIT 3
```

Content-Type は `application/vnd.olrapi.dataview.dql+txt`。

インストール済みプラグインの `main.js:90622` 付近の `searchQueryPost` には `application/vnd.olrapi.jsonlogic+json` のハンドラーだけがある。未登録の Content-Type は 40012 を返す。公開されている 5.1.0 のソースとも照合した。

したがってヘッダーの単純な綴り間違いや Tunnel がヘッダーを壊した問題ではなく、クライアントとサーバーの API 互換性の問題。本文も DQL なので、Content-Type だけ JSON に変更しても直らない。Dataview プラグインの追加だけでも、このハンドラーは復活しない。

共有クライアントの `tests/test_obsidian_requests.py:173` は、HTTP 呼び出しをモックし、DQL 形式を送ることを期待している。`tests/test_tools.py:226` 以降も引数や呼び出しを検証している。専用 gateway の統合テストは、この検索形式を実 REST API に通していない。既存テストの成功は 5.1.0 との互換性を保証していなかった。

REST API の manifest の更新時刻は 8月26日、共有クライアントの更新時刻は 9月20日だった。ファイル時刻だけでは変更履歴を証明できないが、「再接続により新しく壊れた」とする証拠はない。

## 再接続前の障害について分かること

確認した `tunnel/launchd-runtime.log` の期間は 9月20日23:31〜9月22日11:40（JST）。

- 9月20日23:32の終了コード143は、同日の設定記録にある SIGTERM 後の自動復帰試験と整合する。今回の障害原因とは扱わない。
- その後の再起動、認証拒否、通信エラーは、このログに記録されていない。ただし記録がないことだけで障害がなかったとはいえない。
- 9月22日11:35〜11:40には MCP へのリクエスト転送が記録されている。
- 指定された9月22日7:50を含む7:00〜9:00の Tunnel ログは0件。直前の記録は9月20日23:49:32、直後は9月22日11:35:59の転送記録。7:50の要求がローカル MCP に届いた証拠はなく、ChatGPT / OpenAI 側または到達前の問題が候補となるが、ログの不在だけでは発生箇所を確定できない。
- `pmset -g log` の6:30〜9:00台にはスリープ・復帰イベントがなく、7:45〜7:55には Caffeine の活動記録が132件ある。この時刻の Mac スリープを原因とする証拠もない。
- stderr の先頭に `Received request before initialization was complete` が1件ある。タイムスタンプがなく、今回の失敗と対応付けられない。認証エラーそのものを示すメッセージではない。
- 転送ログにツール名、ツールの成功・失敗、返却エラーがなく、ChatGPT の「認証エラー」との照合ができない。

再接続が有効だったことはユーザー報告として確認できるが、それだけで OAuth トークン失効などを原因に確定することはできない。元のエラー原文が得られれば追加照合する。

## 残る対応（優先順）

1. Recent Changes を JSONLogic に変更する。固定された内部クエリで `stat.mtime` を絞り込み、更新時刻も返させ、クライアント側で降順整列と件数制限を行う。既存 DQL の「当日0時から N 日前」という期間境界、返却形式、空結果をテストする。任意 JSONLogic ツールを ChatGPT に公開する必要はない。
2. 対応する実 API バージョンとの契約テストと、公開する読み取りツールのスモークテストを追加する。現行テストは未対応形式を正解として固定しているため、期待値の見直しが必要。
3. gateway に時刻・ツール名・結果・処理時間・秘匿化したエラーコードを記録する。引数、ノート本文、API キーを記録しない。認証・初期化・バックエンドエラーを区別できるようにする。
4. Tunnel の生存確認と Vault 操作の正常性を別々に確認する。GUI ログイン、Obsidian 起動、ネットワーク到達性が必要で、Mac 再起動・スリープ復帰後の一連の動作は別途検証が必要。

共有クライアントは Codex / Claude Code でも使われるため、共有側で修正する場合はそれらへの影響も検証する。

## Git管理側の修正・検証結果（2026-09-22）

作業ディレクトリは `/Users/foreignlab/Documents/ghq/github.com/foreignlab/obsidian-chatgpt-mcp`。プロジェクト改名後のGit管理側で実装した。

- 固定JSONLogicクエリの `if`・`>=`・`stat.mtime` で期間を絞り込み、条件を満たす更新時刻をミリ秒の数値で取得する。
- 期間はMCPプロセスのローカル時刻で「当日0時からN暦日前以降」。現在時刻からのN×24時間には変更しない。日数を引いた後に対象日のUTCオフセットを解決し、夏時間をまたぐ境界を扱う。従来のObsidian側DQLと同じ境界にするには両プロセスのタイムゾーンを揃える。
- 更新時刻の降順、同時刻ならファイル名の昇順で並べてから `limit` を適用する。
- 公開する返却形式は `filename` と `result["file.mtime"]` を維持する。時刻はミリ秒・UTCオフセット付きISO 8601文字列。旧DQLのテーブル列の返却構造は[旧REST API 3.2.0の実装](https://github.com/coddingtonbear/obsidian-local-rest-api/blob/3.2.0/src/requestHandler.ts#L984-L1011)でも確認した。
- 既存の `search_json` を再利用し、TLS検証、タイムアウト、APIエラー処理を維持した。ChatGPTのツール許可リスト・書き込み制限は変更していない。
